# Запустить систему школьного расписания

«Ритм» составляет недельное расписание, проверяет ручные изменения и сохраняет версии. Приложение работает локально на русском языке. [Руководство администратора](docs/ADMIN_GUIDE.md) описывает заполнение данных и публикацию.

## Запуск в Windows

В этой папке уже установлены зависимости и собран интерфейс. Откройте `Start.cmd` либо выполните команду из папки проекта:

```powershell
.\Start.ps1
```

Откройте [локальное приложение](http://127.0.0.1:8000). При первом входе создайте пароль длиной от 12 символов, затем замените его постоянным. Готового пароля в проекте нет.

Остановите сервер сочетанием `Ctrl+C`. Данные останутся в `data/school.db`. Для другого порта выполните:

```powershell
.\Start.ps1 -Port 8010
```

На новом компьютере установите Python 3.12 и Node.js 24. Скрипт создаст окружение, загрузит зависимости и соберёт интерфейс. Интернет нужен при установке, а не при ежедневной работе.

## Запуск через Docker Compose

Установите и запустите Docker Desktop. Скопируйте `.env.example` в `.env` и замените значение `DATABASE_PASSWORD` длинным случайным паролем из букв и цифр. Затем выполните:

```powershell
docker compose up --build -d
```

Откройте [приложение в Docker](http://127.0.0.1:8000). PostgreSQL сохраняет данные в томе `school_data`. Команда `docker compose down` останавливает контейнеры, сохраняя том. Параметр `-v` удаляет данные, поэтому не используйте его для обычной остановки.

На машине разработки Docker Engine не запущен. Конфигурация подготовлена, но сборка контейнера и работа с PostgreSQL на ней не проверялись. Проверенный вариант запуска использует SQLite.

## Проверить проект

Запустите серверные тесты и сборку интерфейса:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
npm run build
```

Браузерный тест создаёт отдельную базу в `.runtime`, сам собирает интерфейс и запускает приложение на порту 8001. Сборка выполняется тестом, поэтому проверяется текущий код из `src`, а не прежняя сборка в `dist`; ошибки типов останавливают тест. Для первого запуска установите Chromium:

```powershell
npx playwright install chromium
npm run test:e2e
```

Измерьте время составления эталонного расписания:

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark
```

Результаты находятся в [отчёте проверки](reports/VERIFICATION.md). Машинные параметры и последнее измерение сохраняются в [benchmark.json](reports/benchmark.json). Найденные при аудите дефекты и усиление решателя описаны в [отчёте аудита](reports/AUDIT.md).

## Изменить интерфейс

В одном терминале запустите API, в другом запустите интерфейс разработки:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
npm run dev
```

Откройте [интерфейс разработки](http://127.0.0.1:5173). После правок выполните `npm run build` и перезапустите локальный сервер. Схема API доступна после входа по адресу `/api/openapi.json`.

## Где находятся данные и настройки

| Объект                                               | Расположение                 |
| ---------------------------------------------------- | ---------------------------- |
| Локальная база, пользователь, версии и журнал        | `data/school.db`             |
| База Docker                                          | Том PostgreSQL `school_data` |
| Подключение к другой базе                            | Переменная `DATABASE_URL`    |
| Разрешённый адрес браузера при нестандартном запуске | Переменная `APP_ORIGIN`      |
| Дополнительный шрифт PDF                             | Переменная `PDF_FONT`        |
| Исходное техническое задание                         | `TECHNICAL_SPECIFICATION.md` |
| Архитектура и ограничения                            | `docs/ARCHITECTURE.md`       |

Приложение по умолчанию доступно только на вашем компьютере. Для работы по сети отдельно настройте HTTPS, разрешённый адрес и сетевой доступ. Автоматическое резервное копирование не входит в эту версию.
