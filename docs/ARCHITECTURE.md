# Архитектура и границы реализации

Приложение состоит из одного Python-сервера, собранного React-интерфейса и базы данных. SQLite обслуживает локальный запуск, PostgreSQL предусмотрен для Docker Compose. Общий слой SQLAlchemy хранит одинаковые структуры в обеих базах.

Назначение документов зафиксировано в [плане документации](CONTENT_PLAN.md).

## Модули

| Файл или каталог                 | Ответственность                                                            |
| -------------------------------- | -------------------------------------------------------------------------- |
| `backend/domain.py`              | Схемы входных данных, ссылки, нормативы и звонки                           |
| `backend/scheduling.py`          | Занятия из учебного плана, доступность, независимая проверка и оценка      |
| `backend/solver.py`              | Модель Google OR-Tools CP-SAT, жёсткие и мягкие ограничения                |
| `backend/hints.py`               | Ограниченная по времени жадная подсказка решателю без перебора и возвратов |
| `backend/recommendations.py`     | Предложения альтернатив и объединения                                      |
| `backend/storage.py`             | Транзакции, версии, задания и журнал                                       |
| `backend/main.py`                | API, сессии, очередь расчётов и жизненный цикл                             |
| `backend/exports.py`             | CSV, XLSX и PDF из снимка версии                                           |
| `src/components/schema-form.tsx` | Формы по серверным схемам без редактора JSON                               |
| `src/pages/schedule.tsx`         | Сетка, ручной редактор, версии, ремонт и экспорт                           |

## Хранение и проверка

Изменения справочников используют номер ревизии для защиты от потери параллельных правок. Запись справочника и действие в журнале сохраняются одной транзакцией. Версия расписания содержит снимок исходных данных; редактирование и восстановление создают новые версии.

Генерация работает вне потока обработки запросов. Сохраняются снимок, параметры, seed, версия OR-Tools, время и результат. После перезапуска незавершённые задания получают статус прерывания. Неизменяемость журнала обеспечивается отсутствием операций изменения и удаления в API; администратор самой базы сохраняет технический доступ.

Одинаковые кабинеты образуют взаимозаменяемую группу в модели. После расчёта назначаются конкретные номера, причём ручные фиксации сохраняются. Независимый валидатор проверяет полученное расписание до сохранения и публикации.

Пожелания решателя и оценка качества описывают одни и те же величины: у каждой мягкой цели есть слагаемое в модели и правило в `score()`. К ним относятся окна и нагрузка преподавателей, сложность предметов, равномерность предметов по дням недели, положение контрольных и сложных предметов, смена кабинетов и базовый кабинет преподавателя, а также сохранение прежнего размещения при повторном расчёте. Сохранение размещения применяется ко всем незаблокированным занятиям исходной версии, а `preferred` взвешивается сильнее. Штраф модели за пропущенный обязательный урок всегда перевешивает сумму всех пожеланий.

Начальная жадная подсказка не доказывает невозможность решения. Она служит исходным размещением для CP-SAT и может стать допустимым запасным результатом только после независимой проверки. Подгруппы, объединения и обязательные пары обрабатывает модель ограничений.

## Безопасность

Пароль хранится как Argon2id-хеш. Cookie сессии имеет `HttpOnly` и `SameSite=Strict`, а при HTTPS также `Secure`. Изменяющие запросы требуют CSRF-токен. Сервер проверяет источник запросов, ограничивает попытки входа и отклоняет незаявленные поля.

Данные не передаются внешним сервисам при обычной работе. SQLAlchemy параметризует запросы. React экранирует текст, экспорт обезвреживает формулы, а сервер выдаёт заголовки защиты. Реальная база, окружение и секреты исключены из Git и Docker-контекста.

## Практические ограничения

Учитывайте следующие свойства реализации:

- Лимит расчёта включает резерв для проверки результата. Время на произвольном наборе зависит от числа вариантов и ограничений.
- Восемь потоков CP-SAT ускоряют поиск, но не гарантируют побитовое воспроизведение результата. Seed и входной снимок сохраняются.
- Статус полного расписания означает выполнение обязательных правил, а не математически доказанный минимум всех пожеланий.
- Приоритеты пожеланий задают взвешенную цель. Смена конкретных взаимозаменяемых кабинетов дополнительно уменьшается на этапе назначения номеров. Два одинаковых кабинета считаются одним кабинетом: их замена не является сменой кабинета.
- Расчёт сначала ищет полное расписание без оптимизации пожеланий и только затем улучшает их на оставшемся времени. Поэтому на медленной машине пожелания могут остаться не полностью сглаженными, но обязательные правила выполняются.
- Проверяемые рекомендации охватывают квалифицированные альтернативы и совместимое объединение. Сверхурочная работа, экстренная квалификация и онлайн-занятия автоматически не назначаются.
- Текущая тема хранится в строке плана. Генерация нумерует занятия последовательно, но не подтверждает фактическое проведение уроков. Перед новой учебной неделей администратор обновляет текущую тему.
- Учебные периоды хранят даты; блокировки каникул и праздников задаются отдельными календарными исключениями.
- Нормативные пределы подтверждает школа. Начальные данные не заменяют проверку применимых нормативных актов.
- Docker/PostgreSQL подготовлены, но не запускались в текущем окружении: Docker Engine недоступен.

## Смены и демонстрационные данные

Две смены используют единую хронологическую сетку из 5–16 звонков. У класса и звонка есть номер смены. Размер кодирования дня равен `max(8, число звонков)`, поэтому прежние односменные снимки не требуют миграции. Генератор, независимая проверка, ремонт, редактор и экспорт используют сетку своего снимка.

Демонстрационный режим сохраняет исходные справочники в таблице `demo_backup` перед первым переключением. Замена и возврат выполняются транзакционно с проверкой ревизии. У каждого опыта отдельный идентификатор, по которому фильтруются версии. Пароль и учётная запись общие; переключение режима не меняет настройки доступа. Демонстрационный режим относится ко всей установке: другие открытые вкладки нужно обновить.
