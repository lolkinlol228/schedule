# План документации

Документы помогают администратору запустить систему и составить расписание, а разработчику проверить реализацию.

| Документ                  | Аудитория                   | Цель                                   | Содержание                                               |
| ------------------------- | --------------------------- | -------------------------------------- | -------------------------------------------------------- |
| `README.md`               | Администратор и разработчик | Запустить приложение                   | Windows, Docker, проверки, пути данных                   |
| `ADMIN_GUIDE.md`          | Завуч                       | Заполнить данные и опубликовать неделю | Справочники, правила, генерация, правки, замены, экспорт |
| `ARCHITECTURE.md`         | Разработчик                 | Найти реализацию и её ограничения      | Модули, хранение, решатель, безопасность, навыки         |
| `reports/VERIFICATION.md` | Ответственный за приёмку    | Проверить подтверждённые результаты    | Команды, тесты, эталон, интерфейс, аудит                 |

Открытым остаётся подтверждение школой нормативов и проверка Docker/PostgreSQL на машине с работающим Docker Engine.
